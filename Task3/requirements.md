## Требования к безопасности
1) ***Конфиденциальность***: передача персональных данных владельцев должна быть зашифрована (TLS 1.3+).
2) ***Контроль доступа к физическим объектам***: каждый запрос на открытие двери/шлагбаума должен логироваться с привязкой к пользователю, времени и устройству.
3) ***Хранение биометрии***: биометрические шаблоны не должны передаваться в открытом виде; на стороне партнёра допускается хранить только их хешированные/обезличенные версии.
4) ***Минимизация данных***: передавать только результат распознавания («доступ разрешён/запрещён» + ID пользователя).

## Протокол аутентификации и авторизации

OAuth 2.0 с грантом client_credentials (для серверного взаимодействия) или Mutual TLS (mTLS) для строгой идентификации сторон. Каждому сервису (домофон, шлагбаум) выдаётся отдельный client_id / client_secret.

## Взаимодействие между системами предприятия и внешней платформой

### Тип интеграции
Асинхронно-синхронная гибридная:

- Синхронные запросы: проверка доступа по звонку (пользователь нажимает кнопку в приложении → нужно быстрое решение).

- Асинхронные события: добавление/удаление пользователей из белого списка, обновление биометрии, логирование событий (кто открыл дверь).

### Сценарии взаимодействия
#### Сценарий 1. Добавление лица для автоматического доступа
1) Пользователь делает фото в приложении.
2) Приложение отправляет фото в PropDevelopment (только после согласия на обработку биометрии).
3) PropDevelopment проверяет права пользователя на доступ к подъезду.
4) PropDevelopment отправляет запрос на платформу партнёра.
5) Платформа партнёра генерирует шаблон лица (без сохранения исходного фото) и связывает с внутренним ID устройства домофона.

#### Сценарий 2. Открытие по распознаванию лица на домофоне
1) Домофон считывает лицо → формирует шаблон.
2) Домофон отправляет запрос на платформу партнёра (локально или через облако партнёра).
3) Платформа партнёра проверяет по своему белому списку.
4) При совпадении → домофон открывает дверь и отправляет асинхронное событие в PropDevelopment: { event: "access_granted", user_id: X, timestamp, device_id }.
5) PropDevelopment сохраняет событие для аудита и отображения в ленте активности приложения.

#### Сценарий 3. Открытие шлагбаума по номеру авто
1) Аналогично сценарию 2, но распознавание выполняется камерой шлагбаума.

#### Сценарий 4. Открытие по звонку через приложение
1) Пользователь нажимает «Открыть дверь» напротив конкретного домофона в приложении.
2) PropDevelopment проверяет, есть ли у пользователя активный доступ к этой двери (собственник/арендатор).
3) PropDevelopment синхронно вызывает POST /v1/access/remote_open на платформе партнёра с указанием device_id, user_id, reason="app_button".
4) Платформа партнёра отправляет команду на домофон (обычно MQTT с QoS 1).
5) Ответ клиенту: успех/ошибка (таймаут не более 3 секунд).
